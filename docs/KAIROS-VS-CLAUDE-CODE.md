# Differenze rispetto a Claude Code

Confronto del **1 novembre 2026** fra il working tree corrente di KAIROS e la documentazione ufficiale di Claude Code. La presenza di una funzionalità non dimostra parità di qualità, affidabilità o prestazioni dei modelli. Non sono stati eseguiti confronti di inferenza fra provider.

KAIROS include già sessioni persistenti e ripresa ricercabile, rinomina/branch, compattazione, plan mode, skill/plugin, MCP di base, permessi per categoria con approvazioni, undo durevole degli edit, riferimenti a file/simboli con budget, ultimo modello ricordato, steering, domande laterali, JSONL/RPC/SDK e coda FIFO selezionabile/modificabile con tastiera. La coda si sospende durante la modifica mentre il turno attivo prosegue.

Sono stati aggiunti anche **permessi granulari, task shell supervisionati, memoria del progetto/istruzioni annidate e rewind per prompt**. Configurazione, comandi e limiti nella [guida avanzata](ADVANCED-WORKFLOWS.md).

| Area | KAIROS attuale | Differenza ancora da colmare |
| --- | --- | --- |
| Permessi e isolamento | Regole per percorsi canonici, comandi completi e nomi esterni, con deny prioritari; isolamento shell opzionale Linux/WSL2 tramite bubblewrap. | Restano policy di rete per dominio e backend filesystem/rete nativi macOS/Windows. La supervisione dei processi Windows non equivale a isolamento filesystem/rete. [Permessi Claude](https://code.claude.com/docs/en/permissions), [sandbox](https://code.claude.com/docs/en/sandboxing). |
| Processi in background | ID, elenco/stato/log/stop, timeout e supervisione dei discendenti; Windows Job Object e gruppo di processi POSIX. | La funzione di base è ora presente; KAIROS mantiene limiti espliciti di runtime, output e numero di task. [Background Bash Claude](https://code.claude.com/docs/en/interactive-mode#background-bash-commands). |
| Memoria e istruzioni | Note durevoli per progetto, proposte dal modello con policy/anteprima e gestione manuale; `AGENTS.md` antenati con workspace fidato. | La funzione di base è ora presente; injection e archivi restano limitati, con opt-out e senza inferenze automatiche separate. La qualità del recupero non è stata confrontata. [Memoria Claude](https://code.claude.com/docs/en/memory). |
| Ripristino | `/rewind` seleziona un prompt e ripristina conversazione, edit registrati o entrambi; `/undo` rimane disponibile. | Restano compattazione selettiva e copertura degli effetti fuori dal journal. Anche Claude non tratta il rewind come backup completo di shell/altre sessioni. [Checkpointing](https://code.claude.com/docs/en/checkpointing). |
| Hook | Eventi tipizzati e plugin con `onTurnEnd`. | Hook configurabili prima/dopo tool, avvio/ripresa sessione e compattazione, con output validato e facoltà esplicite di blocco. Un evento informativo non equivale a una policy eseguibile. [Hooks](https://code.claude.com/docs/en/hooks). |
| MCP interattivo | stdio e Streamable HTTP, tool e risorse, validazione degli schemi. | Login OAuth nel browser, elicitation con domande all'utente e prompt MCP come comandi. [MCP](https://code.claude.com/docs/en/mcp). |
| Subagenti e isolamento Git | `/btw` usa un contesto separato senza tool; `/branch` crea una copia della sessione. | Worker con tool, contesti/permessi dedicati e risultati riportati al padre; supervisione e worktree gestiti. [Subagents](https://code.claude.com/docs/en/sub-agents). Qualsiasi implementazione deve mantenere il coordinamento NIM condiviso fra richieste e processi. |
| IDE e diagnostica | Grafo AST locale, riferimenti e protocollo RPC/SDK. | Estensione IDE distribuita, contesto automatico da selezione/file aperto e gestione LSP con diagnostica dopo gli edit. [VS Code](https://code.claude.com/docs/en/vs-code), [LSP](https://code.claude.com/docs/en/plugins-reference#lspservers). |

Altre differenze di prodotto sono ingresso immagini, strumenti web e flussi Git/PR integrati. KAIROS può già accedere a servizi web o Git attraverso shell, plugin o MCP configurati: manca l'integrazione diretta nella UX. Le immagini richiederebbero anche verifica delle capacità del singolo endpoint NIM. Riferimenti: [immagini e file nell'IDE](https://code.claude.com/docs/en/vs-code#attach-images-and-files), [tool web nel contratto dei hook](https://code.claude.com/docs/en/hooks#pretooluse), [Git nell'IDE](https://code.claude.com/docs/en/vs-code#work-with-git).

Prossime aree rimaste: **hook → MCP interattivo → subagenti → IDE/LSP**, insieme agli affinamenti di isolamento e ripristino indicati sopra. È una proposta basata sull'utilità e sul costo di implementazione, non un ordine prescritto da Claude Code. I subagenti richiedono budget e pacing condivisi: aggiungerli senza questi vincoli aggraverebbe il limite di 40 RPM.

Riscontri locali principali: `src/core/permissions.ts`, `src/tools/registry.ts`, `src/tools/fs-tools.ts`, `src/core/agent-loop.ts`, `src/core/session-store.ts`, `src/extensions/host.ts`, `src/extensions/mcp.ts`, `src/integrations/rpc.ts` e `src/ui/controller.ts`. La precedente [ricerca sul repository pubblico](CLAUDE-CODE-RESEARCH.md) resta una fotografia storica, con le proprie fonti e limiti di accesso al codice.
